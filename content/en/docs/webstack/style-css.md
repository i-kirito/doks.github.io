## 设计目标

样式调整不只是换颜色，而是让页面更容易长期维护：

- 首页要能快速扫到分类和入口。
- 文档页要有稳定的侧栏、正文宽度和目录层级。
- 深色模式下文字、代码块、提示块要有足够对比度。
- 移动端不应出现按钮文字溢出、卡片挤压或导航遮挡。

## 首页卡片

导航站首页卡片建议保持统一结构：

| 元素 | 说明 |
|---|---|
| 图标 | 优先使用站点 favicon 或稳定的远程图标服务 |
| 标题 | 保持短名称，避免整句描述 |
| 描述 | 一句话说明用途 |
| 状态点 | 绿色代表在线，红色代表异常 |

## 文档页

文档页优先保证阅读体验：

- 正文宽度控制在适合长文阅读的范围。
- 标题层级从 `h2` 开始组织内容，不跳级。
- 命令使用代码块，路径和文件名使用行内代码。
- 长列表拆成小节，避免一屏全是项目符号。

## 深色模式

深色模式使用中性黑灰作为底色，蓝紫色作为强调色。这样既接近现代文档站风格，也能避免页面被单一色相占满。

推荐检查项：

- 导航栏、侧栏和正文背景是否有层次。
- 链接颜色在正文和卡片中是否足够明显。
- 代码块和提示块是否能和普通段落区分。
- 搜索框、切换按钮、分页导航是否能在深色背景上识别。

## 发布前检查

每次样式调整后至少检查：

1. 首页首屏。
2. `/docs/` 文档索引。
3. 一篇包含代码块、提示块和目录的文档页。
4. 手机宽度下的导航菜单和卡片换行。
